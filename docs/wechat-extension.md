# 微信扩展边界

当前 upstream（92b5a63）未发现运行时加载第三方视图/数据源的插件契约；Tauri 内置插件是构建依赖，不是用户可安装的 DigUp 扩展。当前交付仍需要我们的构建，不能宣传为原版安装插件即可使用。此项目尚未发布，不为旧版宿主维护兼容适配层。

已实现的分层：

- 读取器进程负责已授权本机微信的数据访问。
- DigUpKit 的 WeChatReader、WeChatMomentsProviding 负责有界调用、数据校验与类型模型。
- SwiftUI 仅呈现模型；Skill 调用 CLI 的只读命令。

若要原版内嵌查看，宿主至少需要：扩展发现与显式启用、版本化能力协议、受限的进程通信、侧栏/页面注册、只读数据授权和撤销、超时与退出回收。朋友圈属于独立数据源，不混成普通聊天会话；缓存覆盖范围必须保留。

建议先定义一个最小宿主接口和微信 provider，再考虑让 upstream 采纳接口。未经用户明确改变原有约束，不能向 upstream 提 PR 或推送。若 upstream 不提供接口，只能做独立伴随应用/Skill 或继续维护 fork；独立窗口不能称为原版内嵌插件。

媒体当前只呈现数量与不可预览提示，不把远程媒体 URL、token 或 key 直接交给 UI。后续媒体能力应通过 provider 输出已验证的本地资源句柄。
