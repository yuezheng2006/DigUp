# 微信扩展边界

当前 upstream（92b5a63）未发现运行时加载第三方视图/数据源的插件契约；Tauri 内置插件是构建依赖，不是用户可安装的 DigUp 扩展。当前交付仍需要我们的构建，不能宣传为原版安装插件即可使用。此项目尚未发布，不为旧版宿主维护兼容适配层。

已实现的分层：

- 读取器进程负责已授权本机微信的数据访问。
- DigUpKit 的 WeChatReader、WeChatMomentsProviding 负责有界调用、数据校验与类型模型。
- SwiftUI 仅呈现模型；Skill 调用 CLI 的只读命令。

若要原版内嵌查看，宿主至少需要：扩展发现与显式启用、版本化能力协议、受限的进程通信、侧栏/页面注册、只读数据授权和撤销、超时与退出回收。朋友圈属于独立数据源，不混成普通聊天会话；缓存覆盖范围必须保留。

建议先定义一个最小宿主接口和微信 provider，再考虑让 upstream 采纳接口。未经用户明确改变原有约束，不能向 upstream 提 PR 或推送。若 upstream 不提供接口，只能做独立伴随应用/Skill 或继续维护 fork；独立窗口不能称为原版内嵌插件。

媒体加载由受限的原生下载和解码路径处理，界面只渲染验证后的图片，不展示 URL、token 或 key。

## 朋友圈图文视图

两列界面以稳定 author_username 选人，不按昵称合并。当前账号由现有 wx config 的数据目录与只读联系人缓存匹配；无法匹配时禁用“我的朋友圈”，不猜测账号。联系人缓存读取使用权限 0700 的临时目录快照，读取后清理；若缓存仍有非空 WAL 则跳过本轮，避免遗漏未合并事务或修改原缓存。头像使用联系人已有地址，图片使用本地朋友圈记录中的凭据请求腾讯 CDN，不扫描密钥、不上传聊天数据。

缩略图通过 SNS token/idx 请求，ISAAC64 流解码。算法实现参考 Bob Jenkins 的 Public Domain C 版本：https://burtleburtle.net/bob/c/isaac64.c 。未将研究过程中看到的 AGPL Python 文件并入产品。下载仅允许 qpic.cn/qlogo.cn 及其子域，强制 HTTPS、校验重定向、单资源上限 8 MiB，解码后生成不超过 800px 的 PNG；不持久化媒体凭据。

广告过滤是可逆的内容规则，不是账号身份鉴定；企业账号只依据 @openim 标识。用户可查看已过滤内容、手动屏蔽作者或始终显示作者，自己的动态不被过滤。图片目前是缩略图，不代表原图归档或视频播放。
